### Task 04: Route `DELETE /api/peers/v1/:name` through `DeletePeer`

**Goal:** Make the peers API delete the peer through `syncing.Server.DeletePeer` so cleanup runs on every successful deletion.

**Context:**
- Read first: `pkg/api/peers.go`, `pkg/cmd/server.go`.
- The existing WireGuard and peer record removal (`PeerController.deletePeer`) stays as is and becomes the `deleteRecord` callback.
- Path, basic auth and responses stay: 204 on success, 500 for unknown peer or record/WireGuard failure, 401 without credentials.

**Acceptance criteria:**
- [ ] DELETE without credentials is rejected and nothing is deleted.
- [ ] DELETE of an unknown peer returns 500.
- [ ] DELETE of a known peer returns 204, goes through `PeerDeleter`, and the peer is gone from peer storage.

**Changes:**
- `pkg/api/peers.go` — add the interface below, take it as a new last parameter of `NewPeersController`, and call it from the DELETE handler with `deletePeer` as the callback.
  `type PeerDeleter interface { DeletePeer(peer string, deleteRecord func() error) error }`
- `pkg/cmd/server.go` — pass the `syncing.Server` instance to `NewPeersController`.
- `pkg/api/peers_test.go` — new file with these cases:
  no credentials returns 401 and does not call the deleter;
  unknown peer returns 500;
  known peer returns 204, the deleter was called with its name, and the peer is gone from storage.

**Validation:** `go build ./... && go test -race ./pkg/api/...`
