### Task 02: Add `AppStateChangeGenerator.RemovePeer`

**Goal:** Withdraw every app a peer last synced and forget the peer, so its exposure goes away and a re-paired peer with the same name gets its apps exposed again.

**Context:**
- Read first: `pkg/syncing/appstate.go`, `pkg/listeners/exposer.go` (`Registry.Watch` consumes the withdraw events and removes exposure and list entries).
- Withdraw events are sent under the generator's lock, then the peer is forgotten.
- A peer that never synced produces no events. Other peers' app lists are untouched.
- `Registry.Watch` is not changed.

**Acceptance criteria:**
- [ ] `RemovePeer(p)` emits one withdraw event per app `p` last synced and none for other peers.
- [ ] A sync from `p` after `RemovePeer(p)` emits add events for its apps again.
- [ ] `RemovePeer` of an unknown peer emits nothing and returns.

**Changes:**
- `pkg/syncing/appstate.go` — add `func (s *AppStateChangeGenerator) RemovePeer(peer string)`, which emits a withdraw event for each of the peer's last synced apps and drops the peer from `peerApps`.
- `pkg/syncing/appstate_test.go` — new file with these cases:
  two peers with an app of the same name: removing one withdraws only its apps, and its next sync re-adds them;
  removing an unknown peer emits nothing.

**Validation:** `go test -race ./pkg/syncing/...`
