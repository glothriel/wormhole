### Task 01: Add `Delete` to `MetadataStorage`

**Goal:** Let every metadata storage implementation forget a peer, so peer deletion can remove the peer's stored metadata from BoltDB and from the in-memory cache in front of it.

**Context:**
- Overall approach for issue #102: `syncing.Server` gets a mutex shared by sync handling and a new `DeletePeer` method; `DeletePeer` deletes the peer record, then the peer's metadata (this task), then withdraws the peer's apps through `AppStateChangeGenerator` (task 02). Wiring happens in task 03.
- `pkg/syncing/metadata.go` defines `MetadataStorage` (`List`, `Set`, `Get`) and three implementations: `inMemoryMetadataStorage` (map guarded by `mutex`), `boltMetadataStorage` (bucket `"metadata"`, key = peer name), `cachingMetadataStorage` (writes go to `storage` first, then `cache`). `ErrPeerNotFound` is returned by `Get` for a missing peer.
- No other type in the repository implements `MetadataStorage` (checked with grep), so no mocks need updating.
- Rule: deleting a peer that has no metadata is not an error; every implementation returns `nil` in that case.
- Rule: `cachingMetadataStorage.Delete` deletes from the child storage first; if that fails it returns the error and leaves the cache untouched (same order and error handling as its `Set`).
- `bolt.Bucket.Delete` returns `nil` for a missing key.
- `NewBoltMetadataStorage` holds an exclusive file lock; a test that reopens the same file must close the first DB first. `boltMetadataStorage` has no `Close` method; the test (package `syncing`) closes it via `s.(*boltMetadataStorage).db.Close()`. Do not add a `Close` method.
- Tests use `github.com/stretchr/testify/assert` and the `// given / // when / // then` comment style of `pkg/syncing/client_test.go`.

**Acceptance criteria:**
- [ ] `MetadataStorage` has `Delete(peer string) error`, implemented by all three storages.
- [ ] After `Delete(p)`, `Get(p)` returns `ErrPeerNotFound` for in-memory, BoltDB and caching storage, and other peers' metadata is still returned.
- [ ] A new BoltDB storage opened on the same file after `Delete` returns `ErrPeerNotFound` for the deleted peer.
- [ ] `Delete` of an unknown peer returns `nil` for all three storages.

**Changes:**
- `pkg/syncing/metadata.go` — add `Delete(peer string) error` to the `MetadataStorage` interface, between `Set` and `Get`.
- `pkg/syncing/metadata.go` — add `func (s *inMemoryMetadataStorage) Delete(peer string) error`: lock `s.mutex`, `delete(s.data, peer)`, return `nil`.
- `pkg/syncing/metadata.go` — add `func (s *boltMetadataStorage) Delete(peer string) error`: `s.db.Update(func(tx *bolt.Tx) error { return tx.Bucket([]byte("metadata")).Delete([]byte(peer)) })`.
- `pkg/syncing/metadata.go` — add `func (s *cachingMetadataStorage) Delete(peer string) error`: call `s.storage.Delete(peer)`, return its error if non-nil, then return `s.cache.Delete(peer)`.
- `pkg/syncing/metadata_test.go` — new file, package `syncing`:
- `pkg/syncing/metadata_test.go` — `TestInMemoryMetadataStorageDelete`: `Set("p1", Metadata{"k": "v"})`, `Set("p2", ...)`, `Delete("p1")` returns nil, `Get("p1")` returns `ErrPeerNotFound`, `Get("p2")` returns its metadata; `Delete("unknown")` returns nil.
- `pkg/syncing/metadata_test.go` — `TestBoltMetadataStorageDeleteIsPersisted`: `NewBoltMetadataStorage(filepath.Join(t.TempDir(), "metadata.db"))`, set `p1` and `p2`, `Delete("p1")`, assert `Get("p1")` is `ErrPeerNotFound`; close via `storage.(*boltMetadataStorage).db.Close()`; reopen with `NewBoltMetadataStorage` on the same path; assert `Get("p1")` is `ErrPeerNotFound` and `Get("p2")` returns its metadata; `Delete("unknown")` returns nil; close the reopened DB the same way.
- `pkg/syncing/metadata_test.go` — `TestCachingMetadataStorageDeleteRemovesFromCacheAndChild`: child = `NewBoltMetadataStorage` on a temp path, `storage := NewCachingMetadataStorage(child)`, `Set("p1", ...)`, `Get("p1")` (fills the cache), `Delete("p1")`; assert `storage.Get("p1")` and `child.Get("p1")` both return `ErrPeerNotFound`.
