### Task 01: Add `Delete` to `MetadataStorage`

**Goal:** Let every metadata storage forget a peer, persistently and in the cache.

**Context:**
- Read first: `pkg/syncing/metadata.go`.
- Deleting a peer that has no metadata is not an error.
- The caching storage deletes from its child first; if that fails it returns the error and leaves the cache as is (same order as its `Set`).
- No other type implements `MetadataStorage`.

**Acceptance criteria:**
- [ ] After `Delete(p)`, `Get(p)` returns `ErrPeerNotFound` in all three storages; other peers are untouched.
- [ ] The deletion survives reopening the BoltDB file.
- [ ] `Delete` of an unknown peer returns nil.

**Changes:**
- `pkg/syncing/metadata.go` — add `Delete(peer string) error` to `MetadataStorage` and implement it in the in-memory, BoltDB and caching storages.
- `pkg/syncing/metadata_test.go` — new file with these cases:
  in-memory: delete removes only the given peer, and deleting an unknown peer returns nil;
  BoltDB: delete is persisted (close, reopen the same file, still not found; other peer still present);
  caching over BoltDB: delete after a cached `Get` removes the peer from both cache and child.

**Validation:** `go test -race ./pkg/syncing/...`
